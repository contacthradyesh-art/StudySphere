BONUS FIX — Map Practice page.tsx
==================================
Your screenshot showed 4 TypeScript errors in map-practice/page.tsx:
"Cannot find name 'normalizeName'" and "Cannot find name 'getFeatureName'".

ROOT CAUSE: the GeoJSON file (public/data/india-states.geojson) is actually
DISTRICT-level (759 features), not state-level. Its properties look like
{ st_nm: "Mizoram", district: "Aizawl", dt_code: "261", ... } — there's no
"name" field. The page's type declared `{ name: string }` and called two
helper functions that were never written, so it never compiled.

FIXED:
- Added getFeatureName() — reads st_nm (falls back to name/NAME_1 for
  future-proofing).
- Added normalizeName() — trim + lowercase for safe comparisons (the st_nm
  values already match your INDIA_STATES list exactly, so no fuzzy matching
  needed).
- Fixed the StateFeature type to reflect the real properties shape.
- De-duplicated state names before starting the "Identify Quiz" — since the
  file has ~20 district polygons per state, without this a state could be
  asked multiple times in one round.
- Fixed a React key collision — every district polygon of the same state
  was using the state name as its key; now uses dt_code (unique per
  district) instead.

This file is now added to the ZIP (4th file total). Same steps apply — just
copy the src folder over and it's included automatically.

FIX #3 — POST /generate-vocabulary returning 500
==================================
Vercel logs showed the Gemini API call actually happened, but then it
failed with a 500 and no console output — because the old code never
logged anything on failure.

LIKELY ROOT CAUSE: BATCH_SIZE was 20 words, each with 8 rich fields
(including Hindi meaning in Devanagari script, synonyms, antonyms, example
sentences, editorial usage) — but maxOutputTokens was only 4000. That's
almost certainly not enough for 20 fully-detailed words, so Gemini's
response was getting cut off mid-JSON, and JSON.parse() failed.

FIXED (generate-vocabulary/route.ts, updated again — 6th file overall):
- BATCH_SIZE reduced 20 → 12 (safer, still fast)
- maxOutputTokens raised 4000 → 8000 (more headroom)
- Added console.error logging at every failure point (Gemini API error,
  empty response, JSON parse failure, unexpected exceptions) — so if it
  ever fails again, Vercel → Logs will show the EXACT reason instead of
  "No logs found for this request"
